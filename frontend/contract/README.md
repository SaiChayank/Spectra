# Frontend contract

Generated by the backend team (docs/frontend-plan.md section 4). Consume it; do not edit it.

* `openapi.json` - `app.openapi()` with sorted keys. The core API routes (auth, users, alerts, incidents, investigations, search, captures, flows, detections, history, status, stats, health, capabilities, interfaces, model, audit, graph) have response models; the frozen experimental modules (pqc/tee/bio/twin/edge, model harden/robustness/evasion/intel) and `/api/metrics` are still untyped (`object`), and free-form sub-objects (alert evidence, pipeline telemetry, graph nodes) are `object` inside a typed envelope: trust the fixtures for those shapes.
* `fixtures/` - real responses recorded from the real app (FastAPI TestClient) against a throwaway data directory seeded
  with the demo captures (baseline, trained model, suspicious captures, incidents). One file per call, named
  `<METHOD>_<path>[__<variant>].json`, each `{request, status, headers, body}`. Variants include `empty` (no data, no
  model), `401`, `403_viewer`, `404`, `409_*`, `422`, `429_throttled` and `503_storage_locked`. `ws_events.json` holds the
  first messages from `/ws/events`. Fixtures are **generated and must not be hand-edited**.
* `proposed/` - shapes for endpoints that do not exist yet (PROPOSED, one file per endpoint, see plan section 6). Empty for now.

Regenerate (from the repository root, with the backend dependencies installed):

    python scripts/export_frontend_contract.py          # rewrite the contract
    python scripts/export_frontend_contract.py --check  # exit 1 if the committed contract is stale (drift guard)

The `--check` run is also a backend test (`backend/tests/test_frontend_contract.py`), so CI fails when a response shape changes
without the contract being regenerated and committed.

## What is normalised (so a re-run is byte-identical)

Passwords, TOTP secrets, otpauth URIs and recovery codes are `<redacted>`; session cookies appear only as cookie names;
absolute paths are `<DATA_DIR>`; wall-clock timestamps become `1800000000` plus whole hours since the run start (expiry = +43200);
random ids (`alrt_*`, `mdl_*`, `cap_*`) and digests/keys/signatures get deterministic stand-ins of the same length; timings
(`*_ms`), queue depths, DB counters, `snn_score` (CPU-sensitive) and the immune-system level/response are constants; host interfaces are fixed examples.
Treat these as shape examples, not real measurements. Synthetic capture timestamps (2023) are as recorded.

## Not recorded

`GET /api/metrics` (Prometheus text, wall-clock counters), live capture start/stop and the experimental POST routes
(pqc/tee/bio/twin/edge, model harden/robustness; frozen modules, no P0 need), TOTP enable/disable success (needs a real secret).

## Things the frontend must know

* Change your own password with `POST /api/auth/password` (any role; fixtures `POST_api_auth_password*.json`). `PATCH /api/users/{id}`
  needs `users:manage` (ADMIN) and is only for resetting someone else (`PATCH_api_users_2__403_viewer_own_password.json`).
* Re-processing an already processed capture returns 200 (no 409).
