## 9B experiment (2026-11-06) — augmentation does not harden the Isolation Forest against evasion.attack
Recorded run (scratch scripts, not committed): demo baseline pcap (make_baseline_pcap n_flows=300 -> 302 benign flows x 39 features), seed 1; attack set = 80 benign rows with 10 features pushed 8-20 sigma out of range; every model fit with random_state=42, contamination 0.02 unless stated. Metric = fraction of the attack set still flagged after `evasion.attack` on every flagged row (comparable across models, unlike `evasion_rate`, whose denominator is the model's own flagged set).
- base model: flags 66.2% of the attack set; 2.5% still flagged after attack (benign false-flag rate 2.3%).
- benign + evaded perturbed vectors: 58.8% -> 0.0% after attack (FP 0.7%).
- benign + shrunk attack points (0.35 toward the mean): 75.0% -> 0.0% (FP 0.7%).
- benign + jittered benign copies x2: 25.0% -> 0.0%.
- contamination 0.05: 91.2% -> 2.5% (FP 5.3%).
Conclusion: none of the tested augmentations lowers the evasion success rate; evasion.attack defeats every variant (~97-100% of flagged rows). An unsupervised Isolation Forest cannot take negative labels, so adding evaded points only teaches it that they are normal. docs/33 §9B step 1 Done-when ("retrained model's evasion success rate drops") is therefore NOT met by this construction. Reproduction: sizes/seeds above; one-off script was in the session scratchpad.

## 9E experiment (2026-11-06) — a recent reference does not catch slow drift sooner than the training baseline
Setup (scratch scripts, not committed): one feature, normal and lognormal; train 5 000 rows, training-range 40-bin PSI as in `SpectraDetector.psi`; stream 100 flows/step with the mean drifting monotonically (0.005 / 0.01 / 0.02 per step); window = last 1 000 flows; 5 seeds. Compared `psi_vs_train` with (a) the window vs a decayed histogram on the same bins and (b) the window vs an 800-flow lagged reference. Thresholds calibrated per method as the maximum PSI seen with ZERO drift (equal false-alarm level), because raw 0.10 is crossed by noise alone.
Result: `psi_vs_train` tripped first in every normal and lognormal case; the decayed reference tripped later (e.g. 61-142 steps later at 0.005/step) and the lagged reference mostly never at 0.005/step. This is structural: a reference built from recent traffic moves with the drift, so its distance to the present is always smaller than the training snapshot's. docs/33 §9E Done-when ("slow monotonic shift trips psi_vs_recent before psi_vs_train") is therefore NOT met and cannot be by a recent-reference construction; `tests/test_drift.py::test_slow_shift_is_caught_by_the_training_psi_first` records the real ordering instead.
What the recent comparison IS good for (tested): it re-baselines after a legitimate step change (train PSI stays moderate/significant forever, recent returns to stable) and it flags an abrupt change against recent history. Alerting therefore fires on the WORSE of the two (`alert_level`), never on recent alone, so no slow-drift detection that exists today is lost.
Side finding in existing code (not changed here): `SpectraDetector.psi` uses 40 linear bins from the training min-max. With a few hundred to a thousand rows the sampling-noise floor of PSI (~bins/n) sits at 0.04-0.18, so same-distribution data can read "moderate" against the training baseline (seen in tests/test_drift.py and the simulation); heavy-tailed features are worse because the min-max range is set by outliers. `refresh_drift_level` already runs from 40 buffered flows. `psi_vs` merges bins 4:1 to lower its own floor; the training comparison is unchanged.

## 9G design notes (2026-11-06) — why hash commitments and not Feldman VSS
docs/33 §9G asks for "public commitments per share". Feldman VSS (commit g^coeff) was rejected: the free coefficient's commitment g^secret is public, and the secrets here are quantized model deltas (integers of at most ~10^7 in magnitude per element), so g^secret is brute-forceable with a lookup table - it would leak every party's update and void the "coordinator learns only the sum" claim. Pedersen VSS (hiding) would work and is additively homomorphic, but it needs the project's own unreviewed secp256k1 code and a batched check (per-share cost ~ dim x t point multiplications in pure Python). Shipped instead: SHA-256 commitments with a secret 128-bit nonce per share (per party share and per aggregate share, domain-separated by round id and owner), plus a polynomial-consistency check when surplus shares exist. That detects tampered/misattributed shares and (with surplus shares) inconsistent dealing; it does NOT detect a malicious dealer who commits to a consistent-looking but wrong aggregate when exactly t shares are supplied. Pedersen VSS remains the documented upgrade.
